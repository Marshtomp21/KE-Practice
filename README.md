# 基于知识图谱的电影 RAG 数据集

本仓库保存课程设计“基于知识图谱的电影/影视作品关系图谱问答系统”第一版语料、粗抽取结果和可复现的数据采集脚本。

数据以中文维基百科影片、演员和导演词条为主要语料来源。影片、演员和导演分别保存为独立实体，实体之间通过出演、执导、编剧、出品、获奖、提名、改编、续作和合作等关系连接，可用于构建 Neo4j 等图数据库，也可以切分正文后建立向量索引，用于 Graph RAG 实验。

## 二、知识图谱 Schema

### 1. 实体类型

本数据集使用以下实体类型：

| 实体类型 | 说明 | 主要文件 |
| --- | --- | --- |
| 影片 | 电影及影视作品 | `films.jsonl` |
| 演员 | 参与影片演出的人员 | `actors.jsonl` |
| 导演 | 执导影片的人员 | `directors.jsonl` |
| 编剧 | 影片编剧或剧本作者 | 作为影片字段和关系目标保存 |
| 制片公司 | 制作、出品影片的公司 | 作为影片字段和关系目标保存 |
| 奖项 | 影片获得或被提名的奖项 | 作为影片字段和关系目标保存 |
| 类型 | 剧情、动作、科幻、喜剧等影片类型 | 作为影片字段和关系目标保存 |
| 角色 | 演员在具体影片中饰演的角色 | 保存在演员关系的 `roles` 字段中 |

### 2. 关系类型

| 关系 | 起点 | 终点 | 说明 |
| --- | --- | --- | --- |
| 执导 | 影片 | 导演 | 某导演执导某部影片 |
| 出演 | 影片 | 演员 | 某演员出演某部影片，可携带角色列表 |
| 编剧 | 影片 | 编剧 | 某人为影片编写剧本 |
| 出品 | 影片 | 制片公司 | 某公司参与影片制作或出品 |
| 获奖 | 影片 | 奖项 | 影片获得某奖项 |
| 提名 | 影片 | 奖项 | 影片获得某奖项提名 |
| 类型 | 影片 | 类型 | 影片属于某个类型 |
| 改编自 | 影片 | 原作或作品 | 影片改编自某部作品 |
| 前作 | 影片 | 影片 | 当前影片的上一部作品 |
| 续作 | 影片 | 影片 | 当前影片的后续作品 |
| 合作 | 人物 | 人物 | 两人在至少一部影片中共同工作 |

`合作`关系是派生关系。系统会汇总两人共同参与的影片，并在 `collaboration_count` 中记录合作次数，可用于回答“某导演的常用班底是谁”等统计问题。

## 四、数据文件说明

### 1. `films.jsonl`

每行是一部影片的完整记录。主要字段如下：

```json
{
  "film": {
    "id": "影片唯一标识",
    "name": "影片名称",
    "entity_type": "影片",
    "year_category": "来源年份分类"
  },
  "directors": [],
  "actors": [],
  "screenwriters": [],
  "production_companies": [],
  "awards_received": [],
  "nominations": [],
  "genres": [],
  "adapted_from": [],
  "previous_works": [],
  "sequels": [],
  "source_document": {
    "intro": "词条导言纯文本",
    "raw_wikitext": "完整维基源文本",
    "url": "来源页面地址",
    "revision_id": "页面修订号"
  }
}
```

`actors` 中的每个演员对象可以包含 `roles` 数组，用于保存该演员在当前影片中饰演的角色。

### 2. `actors.jsonl`

每行是一名演员的独立词条，而不是附属于某一部影片的临时字段。

```json
{
  "person": {
    "id": "人物唯一标识",
    "name": "演员姓名",
    "entity_type": "演员",
    "aliases": []
  },
  "filmography": [
    {
      "id": "影片标识",
      "name": "影片名称",
      "roles": ["角色名称"]
    }
  ],
  "related_film_count": 3,
  "has_wikipedia_text": true,
  "source_document": {}
}
```

`has_wikipedia_text=false` 表示该演员是从影片演员表中抽取出的有效节点，但暂时没有定位到独立中文维基人物页面。此类记录仍保留姓名、关联影片和角色，可在后续阶段使用其他来源补充正文。

### 3. `directors.jsonl`

每行是一名导演的独立词条，结构与演员文件相似。`filmography` 保存其在当前语料范围内执导或关联的影片。

同一个人既可能是演员，也可能是导演。为了符合当前 Schema，他会分别出现在 `actors.jsonl` 和 `directors.jsonl` 中；若有 Wikidata QID，两条记录会使用同一稳定 ID，方便后续合并为多标签人物节点。

### 4. `relations.jsonl`

该文件是适合导入图数据库的扁平关系表，每行表示一条边：

```json
{
  "source_id": "起点实体 ID",
  "source_name": "起点名称",
  "source_type": "影片",
  "relation": "出演",
  "target_id": "终点实体 ID",
  "target_name": "演员姓名",
  "roles": ["角色名称"],
  "evidence_url": "关系证据页面",
  "raw_evidence": "抽取关系时使用的原始文本"
}
```

### 5. `collaborations.jsonl`

该文件保存人物之间的合作统计：

```json
{
  "person_a": {"id": "人物 A ID", "name": "人物 A"},
  "person_b": {"id": "人物 B ID", "name": "人物 B"},
  "relation": "合作",
  "films": [],
  "collaboration_count": 3
}
```

它可以直接支持以下问题：

- A 演员和 B 演员合作过吗？
- 两名演员通过哪些影片产生关联？
- 某导演与哪些演员合作次数最多？
- 哪些人物与同一位导演合作三次以上？

### 6. CSV 清单

- `manifest.csv`：影片清单及导演、演员数量、类型、奖项数量、正文长度等摘要。
- `actor_manifest.csv`：演员清单、关联影片数、人物正文覆盖情况和来源地址。
- `director_manifest.csv`：导演清单、关联影片数、人物正文覆盖情况和来源地址。

CSV 文件使用 UTF-8 with BOM 编码，可以直接使用 Microsoft Excel 打开，不会出现中文乱码。

## 五、语言与编码

所有数据文件均使用 UTF-8 编码。

中文标题、姓名、角色、类别、正文和关系证据已经通过 OpenCC `t2s` 转换为简体中文，并经过二次稳定性检查。外国人名、影片名或公司名如果在中文维基中直接使用英文专名，会保留原文，不进行不可靠的机器音译。

实体 ID 不用于展示：

- 优先使用 Wikidata QID，例如 `Q12345`。
- 没有 QID 但有维基页面时，使用页面 ID。
- 只有名称时，使用 `NAME:` 前缀的临时 ID。

后续清洗时应将临时 ID 与规范实体进行消歧、合并。

## 六、重新生成数据

推荐使用 Python 3.12 或更高版本。

### 1. 安装依赖

```powershell
python -m pip install -r requirements.txt
```

### 2. 批量采集影片页面

```powershell
python -X utf8 scripts\fetch_wikipedia_300_films.py --count 330 --batch-size 15
```

该脚本从中文维基年度影片分类及其子分类中批量取得影片页面，保存完整 wikitext、导言、分类、页面 ID、修订号和来源地址。

### 3. 过滤并补充经典影片

```powershell
python -X utf8 scripts\augment_film_dataset.py
```

该脚本会过滤年度列表、流媒体平台等非影片页面，补充诺兰、王家卫、张艺谋、奉俊昊等导演的代表影片，并粗提取信息框、演员表、类型和奖项字段。

### 4. 生成演员和导演独立词条

```powershell
python -X utf8 scripts\enrich_people_and_simplify.py --batch-size 15 --workers 3
```

该脚本会执行以下操作：

1. 从影片记录中汇总并去重演员和导演。
2. 批量获取可定位的中文维基人物词条。
3. 生成演员、导演独立 JSONL 文件及 CSV 清单。
4. 更新影片中的人物 ID 和显示名称。
5. 重新生成显式关系和合作关系。
6. 使用 OpenCC 将所有中文内容统一为简体中文。

抓取过程中会临时创建断点缓存；全部成功后脚本会自动删除缓存。若任务中断，重新运行同一命令即可从缓存继续。

只需要重新执行繁简归一化时，可以运行：

```powershell
python -X utf8 scripts\enrich_people_and_simplify.py --normalize-only
```

## 七、推荐的知识图谱构建流程

1. 读取 `films.jsonl`、`actors.jsonl` 和 `directors.jsonl`，创建影片、演员和导演节点。
2. 根据 `relations.jsonl` 创建执导、出演、编剧、出品、获奖、提名、改编、前作和续作边。
3. 根据 `collaborations.jsonl` 创建带 `collaboration_count` 权重的合作边。
4. 使用 QID、页面 ID、别名和上下文对 `NAME:` 临时实体做消歧与合并。
5. 将 `intro` 和清洗后的 `raw_wikitext` 按段落切分，建立向量索引。
6. 查询时先识别实体，再执行图路径或聚合查询，最后把图查询结果和相关文本段落交给大模型生成答案。

## 八、可支持的演示问题

- “诺兰导演过哪些片？”：通过影片到导演的单跳关系查询。
- “A 演员和 B 演员合作过吗？”：查询合作边及共同影片列表。
- “通过哪些影片、哪些导演产生关联？”：执行多跳路径查询。
- “某导演的常用班底是谁？”：按合作次数或共同影片数排序。
- “哪些演员和同一位导演合作三次以上？”：按人物和导演分组计数。
- “某演员出演过某片吗？”：检查出演边是否存在，可用于反事实回答。

## 九、已知限制

本数据集是课程设计第一版语料，当前结构化字段属于粗抽取结果：

- 中文维基不同页面的信息框字段并不完全统一，部分导演、演员、编剧和公司字段可能缺失。
- 奖项和提名常以表格或自然语言形式出现，当前覆盖率低于演员、导演等字段。
- 只有 169 部影片成功抽取到明确的演员角色关系。
- `NAME:` 临时实体可能存在同名不同人、译名差异或别名重复，需要进一步实体消歧。
- `has_wikipedia_text=false` 的人物只有关系数据，没有独立人物正文。
- 外国专名可能保留英文，但所有可转换的繁体中文均已转换为简体中文。
- 数据反映抓取时对应的维基页面版本，后续页面更新不会自动同步。

因此，构建正式知识图谱前仍建议进行字段标准化、实体消歧、关系核验、文本分段和抽样质量检查。

## 十、数据来源与许可

结构化关系和正文主要来自中文维基百科页面。每条带正文的记录均保留：

- 来源页面 URL
- 页面 ID
- 修订 ID
- 修订时间
- 抓取时间
- 许可信息

中文维基百科文本通常遵循 CC BY-SA 4.0。展示、修改或重新分发正文及其衍生内容时，应保留适当署名、页面链接和相同方式共享要求。课程报告和系统界面中应明确注明语料来源为中文维基百科。

本仓库中的采集与处理脚本用于课程学习和数据处理实验，不代表维基媒体基金会或相关影视机构。
